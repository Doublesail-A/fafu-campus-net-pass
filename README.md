# fafu-campus-net-pass

给 OpenWrt / Kwrt 增加设备白名单、动态验证码接入、人员分组、按设备代理与网络质量监测。HTTPS 端到端透传，不解密网站内容，不要求手机安装路由器证书。

这是已经在一台约 512MB 内存的 Kwrt 路由器运行的定制方案。仓库包含自编管理代码与部署工具；UA3F、Squid、sing-box、LuCI 等第三方组件通过软件源或其官方项目安装，不随仓库附带二进制或用户凭据。

## 你能用它做什么

| 功能 | 使用方式 |
| --- | --- |
| 控制谁能上网 | 未授权 MAC 可访问登记页，不能访问外网；管理员也可手动授权、覆盖备注与分组 |
| 手机自行登记 | 只输入认证器的 6 位 TOTP；验证码防重放、限流并绑定本机 MAC/IP |
| 整理很多设备 | 按人员分组折叠，备注优先，保留设备名称；新建/移动/重命名分组 |
| IoT 直连 | 经路由器重建 TCP 后直连，不再固定走香港代理 |
| 给某台设备走代理 | 定时或长期，规则或全局；所有手动代理设备共用最后选择的出口节点 |
| 离线更新节点 | 直接上传无后缀的 FlClash/Clash 配置，也支持 HTTPS 订阅 |
| 排查偶发卡顿 | 分别记录 LAN 中继、本机有线、代理出口的 DNS/TCP/TLS/首字节与总耗时 |

私有 MAC 可以登记，但 MAC 轮换、系统恢复出厂后可能出现新记录；旧设备记录需要管理员确认后删除。MAC 白名单适合家庭/宿舍管理，MAC 本身可以被仿冒，不等于强身份认证。

## 验证结论如何理解

抓包已验证受测普通设备、IoT HTTPS 与普通非网页 TCP 的 LAN/WAN 初始序列号独立，证明路由器重新建连。复杂网页测试使用了 Bilibili 的真实首页与资源；网络传输时间不等于浏览器完成脚本执行、登录和渲染的时间。

本项目不把“当前能联网”视为不存在 DPI/风控的证据，也不保证只能被识别为固定数量的设备。规则模式只控制设备请求的出口；HTTPS 中的应用特征继续由客户端产生。
