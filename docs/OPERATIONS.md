# 日常使用

## 登记与设备记录

新设备连接后访问普通HTTP探测页会进入本地登记界面；部分系统不会自动弹出，可以打开 `http://172.31.255.1:8085/`。HTTPS站点不能通过伪造证书强制跳转，所以不会对未知设备做HTTPS劫持。

输入管理员认证器当前的6位码即可。私有MAC允许使用；重置手机或重新生成该网络的私有地址后，MAC可能变化，因此新设备记录与旧记录同时存在是正常现象。不要仅凭相同名称自动覆盖权限，先确认MAC再清理旧记录。

后台手动输入已有MAC会覆盖该设备的设置。备注用于人识别，设备名称保留用于核对；可按人员建组、折叠、批量移动。人员分组仅整理列表，不改变normal/IoT权限或代理。

## 普通组与IoT

两组都不需要CA。IoT经TCP中继后直连；普通组也直连，可以单独启用临时/长期代理。IoT若确需手动代理，先在后台确认是否改为普通组；不要直接修改内核set当作持久设置。

## 节点与订阅

上传FlClash配置时不要限制文件后缀，无后缀配置可以直接选。先核对预览中的支持数量、跳过数量与节点证书验证设置，再导入。只更新节点时不要勾选替换规则。

离线导入成功后，旧订阅地址保留，但定时远端更新暂停，避免夜间覆盖本地工作配置。以后点击“保存并更新订阅”成功才恢复订阅来源。没有可用节点时，也能从电脑重新上传文件。

测速值依赖测速URL、是否包含建连/握手、缓存、出口和并发，不能把FlClash显示的数字直接当成GitHub完整页面延迟。先核对两端配置是否相同，再用同一个目标分阶段测量。

## 给设备设置规则或全局

- 规则：国内命中直连，其余按规则/共用节点处理，需要先准备国内规则集。
- 全局：该设备受控TCP经共用节点；不是所有UDP都支持。
- 长期：不会因期限到达自动撤销。
- 定时：到期由内核timeout恢复普通路径，后台记录也会同步清理。

选择新节点会同步其他手动代理设备的节点；时长、模式继续独立。切换节点可能中断旧代理连接并重新建立。测试节点不会自动修改真实设备权限。

## 停止两天监测

```sh
/usr/sbin/privacy-latency-monitor stop
```

会撤销虚拟测试设备、移除本监测的cron项，保留日志。其他人的授权、原有定时任务和日常看门狗不删除。
